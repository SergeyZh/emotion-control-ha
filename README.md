# ESPHome ↔ L&S Emotion Control (CC2500)

Управление светильниками **L&S Emotion Control** из **Home Assistant** через **ESPHome**:
ESP32 + радиомодуль **CC2500** (2.4 ГГц) воспроизводят протокол оригинального пульта и
дополнительно **слушают эфир**, синхронизируя состояние в HA с нажатиями физического пульта.

**Статус: рабочее.** Поддержано: включение/выключение, цветовая температура, абсолютная
яркость (5 ступеней), сопряжение, приём команд пульта и синхронизация состояния, сохранение
состояния при перезагрузке, поиск ID пульта в эфире. Осталась только опциональная шлифовка.

Протокол полностью расшифрован в репозитории
[`emotion-control-re`](https://github.com/SergeyZh/emotion-control-re) (там же — RF-параметры, формат кадра, дамп
регистров CC2500). План проекта и статус фаз — в [`PLAN.md`](PLAN.md); заметки для ИИ-агентов —
в [`CLAUDE.md`](CLAUDE.md).

## Как это работает
- CC2500 конфигурируется снятой с пульта картой регистров (MSK, 250 kBaud, 2436.2 МГц,
  sync `0xD391`, FEC, whitening off, аппаратный CRC). Всё это чип делает **аппаратно** — софт
  готовит только 14-байтовый payload.
- **Передача:** собираем пакет `0E | ID | cmd | val | 00×6 | chk | 16`
  (`chk = 0x7E ⊕ ID₀⊕ID₁⊕ID₂⊕ID₃ ⊕ 0x16 ⊕ cmd ⊕ val`), пишем в TX FIFO, передаём.
- **Приём:** чип держится в RX; кадры валидируются (CRC, длина, `chk`), и те, что пришли с нашего
  `remote_id`, обновляют состояние в HA **без обратной передачи**. Кадры от любых других пультов
  доступны сниффер-компоненту — так узнаётся ID своего пульта.

## Железо
- **ESP32** (проверено на DevKit V1 / ESP-WROOM-32).
- **Модуль CC2500** — именно 2.4 ГГц (НЕ CC1101), **кварц 26.000 МГц** (иначе снятые RF-регистры
  дадут другую частоту/скорость). Распиновка — [`datasheets/CC2500_module_pinout.md`](datasheets/CC2500_module_pinout.md).
- **Питание модуля — 3.3 В (пин `3V3`), не 5 В.**

### Подключение (модуль CC2500 → ESP32, SPI)
| Модуль | Сигнал | ESP32 (пример, VSPI) |
|---|---|---|
| SI (2) | MOSI | GPIO23 |
| SCLK (3) | SCLK | GPIO18 |
| SO (4) | MISO | GPIO19 |
| CSn (8) | CS | GPIO5 |
| GDO0 (7) | конец передачи (опц.) | GPIO4 |
| VDD (1) / VSS (6) | 3V3 / GND | 3V3 / GND |

`GDO2` не используется. `GDO0` необязателен: если не подключён/не задан, конец передачи
определяется опросом регистра `MARCSTATE`. В приёме `GDO0` не участвует.

## Быстрый старт
```bash
# 1. Установить ESPHome (пример — venv в каталоге проекта)
python3 -m venv .venv
./.venv/bin/pip install esphome

# 2. Узнать ID своего пульта: прошить сниффер и нажать кнопку на пульте
./.venv/bin/esphome run sniffer.yaml --device /dev/cu.usbserial-0001
#    → [I][cc2500_emotion_sniffer]: remote 68049F25  cmd=0x01 (on) ...
#    Подробнее — раздел «Как узнать ID пульта».

# 3. Создать secrets.yaml рядом с example.yaml
printf 'wifi_ssid: "ВашаСеть"\nwifi_password: "пароль"\n' > secrets.yaml

# 4. Вписать найденный ID в remote_id в example.yaml и прошить по USB
#    (первый раз по USB, дальше можно по OTA)
./.venv/bin/esphome run example.yaml --device /dev/cu.usbserial-0001
```
Признак успешной инициализации в логах:
```
CC2500 PARTNUM=0x80 VERSION=0x03
Radio check: SYNC1=0xD3 MDMCFG2=0x73 CHANNR=0x10
Radio configured and calibrated.
Listening for remote commands (RX enabled).
```

## Конфигурация
Компонент лежит в [`components/`](components/) и подключается как external component. Полный
пример — [`example.yaml`](example.yaml); минимальный стенд без Wi-Fi — [`bench.yaml`](bench.yaml).

```yaml
external_components:
  - source:
      type: local
      path: components

spi:
  clk_pin: GPIO18
  mosi_pin: GPIO23
  miso_pin: GPIO19

cc2500_emotion:
  id: emotion
  cs_pin: GPIO5
  gdo0_pin: GPIO4         # опционально
  remote_id: "68049F25"   # ID вашего пульта (4 байта hex) — см. «Как узнать ID пульта»
  receive: true           # слушать эфир и синхронизировать состояние
  step_interval: 200ms    # пауза между посылками шагов яркости

light:
  - platform: cc2500_emotion
    name: "L&S Emotion"
    cc2500_emotion_id: emotion
    brightness_levels: 5              # число ступеней яркости лампы
    ramp_duration: 1000ms            # время полного плавного хода мин↔макс
    cold_white_color_temperature: 6500 K
    warm_white_color_temperature: 2700 K
```

### Опции `cc2500_emotion` (хаб)
| Опция | По умолчанию | Описание |
|---|---|---|
| `cs_pin` | — (обязательно) | CS (CSn) модуля |
| `gdo0_pin` | — (опц.) | GDO0 для тайминга конца передачи; иначе фолбэк на `MARCSTATE` |
| `remote_id` | — (опц.) | 4-байтовый ID пульта (hex, можно с `:`). Без него передача отключена и устройство только слушает эфир |
| `receive` | `true` | Приём команд пульта и синхронизация состояния в HA |
| `step_interval` | `200ms` | Пауза между отдельными посылками шагов яркости (лампа схлопывает слишком частые) |

Плюс стандартные ключи `spi` (`cs_pin` берётся из схемы SPI-устройства).

### Опции платформы `light`
| Опция | По умолчанию | Описание |
|---|---|---|
| `cc2500_emotion_id` | (авто) | Ссылка на хаб `cc2500_emotion` |
| `brightness_levels` | `5` | Число дискретных ступеней яркости лампы |
| `ramp_duration` | `1000ms` | Время полного плавного хода яркости (для оценки ramp от пульта) |
| `cold_white_color_temperature` | `6500 K` | Холодный край цвет. температуры |
| `warm_white_color_temperature` | `2700 K` | Тёплый край цвет. температуры |
| `restore_mode` | `RESTORE_DEFAULT_OFF` | Восстановление состояния при ребуте (переопределён с базового `ALWAYS_OFF`) |
| `gamma_correct` | `1.0` | Линейная (не трогать — иначе ломается маппинг ступеней) |
| `default_transition_length` | `0s` | Плавных переходов у ступенчатого устройства нет |

### Дополнительные кнопки (пример из `example.yaml`)
Реализованы как штатные `template button`, вызывающие методы хаба:
- **Сопряжение** → `id(emotion).send_pair();`
- **Ярче / Темнее** → `id(emotion).brightness_step(1);` / `(-1);` (всегда шлют шаг, ресинхрон UI↔лампа)
- **Raw send** + два текстовых поля (`raw_cmd` / `raw_val`, hex) → `id(emotion).send_raw(cmd, val);`
  — для экспериментов с протоколом прямо из HA, без перепрошивки.

## Как узнать ID пульта
`remote_id` — это 4 байта, которыми ваш пульт подписывает каждую посылку; лампа запомнила их при
сопряжении. У каждого пульта они свои, поэтому значения по умолчанию нет. Узнать свой ID можно
самим же модулем CC2500 — компонентом `cc2500_emotion_sniffer`.

1. Прошить готовый конфиг: `esphome run sniffer.yaml --device /dev/cu.usbserial-0001`.
   В нём `remote_id` не задан, поэтому устройство только слушает и ничего не передаёт.
2. Нажимать кнопки на пультах. Каждый распознанный кадр печатается строкой:
   ```
   [I][cc2500_emotion_sniffer]: remote 68049F25  cmd=0x01 (on)  val=0x80  RSSI=-38 dBm  LQI=2
   ```
3. Свой пульт — тот, у которого `RSSI` заметно выше (он у вас в руках). Найденный ID вписать в
   `remote_id` боевого конфига.

Сниффер видит **все** пульты Emotion в радиусе приёма, а не только ваш: кадр проверяется по
аппаратному CRC и по контрольной сумме, которая считается из самих принятых байт ID, — поэтому
угадывать ID не нужно, он либо сходится, либо кадр отбрасывается.

Неизвестные команды печатаются вместе с полным кадром (14 байт) — в них шесть «резервных» байт
могут оказаться не нулевыми. Это же режим для пополнения карты команд: если ваш пульт умеет что-то,
чего нет в таблице ниже, лог покажет и код, и байты.

### Если приём неустойчив
Пульт повторяет каждое нажатие серией примерно из 5 одинаковых кадров — это и есть защита
протокола от потерь. Сниффер печатает **каждую** копию, поэтому число строк на одно нажатие прямо
показывает качество связи: 4–5 строк — связь здоровая, 1 строка — половина копий теряется, 0 —
кадр не детектируется вовсе.

В строке лога смотрите на `LQI` (счётчик ошибок демодуляции, **0 = идеально**) и на `offset`
(оценка расхождения несущей). Диагностика:

| Симптом | Причина |
|---|---|
| Строк `Frame rejected: CRC failed` много | Сигнал ловится, но кадры бьются — слабый сигнал или помеха |
| Отбраковок нет, но и кадров мало | Приёмник не детектирует передачу: антенна, расстояние, экранирование |
| `offset` стабильно большой в одну сторону | Расхождение кварцев пульта и модуля |
| `offset` скачет ±68 кГц в обе стороны | Это шум оценки на пределе FOC (±BW/8), а не расстройка — компенсировать нечего |
| `RX FIFO overflow` и `length byte 0x…` без нажатий | Ложное срабатывание на шуме Wi-Fi (мы внутри 2.4 ГГц). Безвредно для данных, но крадёт приём; ограничено через `PKTLEN` |
| Пульт читается хуже другого | Проверьте батарейку — севшая даёт ровно «иногда доезжает». Помогает переустановка батарейки |

⚠️ Не пытайтесь «чинить» скачущий `offset` записью в `FSCTRL0`: при шумовой оценке это внесёт
случайную расстройку и сделает приём хуже.

### Список найденных пультов в Home Assistant
Если сниффер стоит в конфиге с Wi-Fi/API, найденные пульты можно смотреть не только в логах, а
прямо в HA — диагностической сущностью со списком:

```yaml
cc2500_emotion_sniffer:
  id: sniffer
  cc2500_emotion_id: emotion

text_sensor:
  - platform: cc2500_emotion_sniffer
    cc2500_emotion_sniffer_id: sniffer
    discovered_remotes:
      name: "Найденные пульты"
```

Состояние — все пульты, услышанные с момента загрузки, с **лучшим** уровнем сигнала каждого:

```
6804F74D -49dBm, 68049F25 -71dBm
```

Нажимаете кнопку на очередном пульте — он появляется в списке. Свой определяется по сигналу: он
у вас в руках, поэтому уровень заметно выше. Берётся именно лучший, а не последний уровень — так
значение сходится и сущность перестаёт обновляться, вместо того чтобы дёргаться на каждом кадре
(при удержании кнопки их ~85 в секунду).

⚠️ **Сущности в ESPHome создаются при компиляции**, поэтому отдельная сущность на каждый
обнаруженный в эфире пульт технически невозможна — `esp32_ble_tracker` устроен так же (в UI
попадают только заранее прописанные в YAML адреса, остальное живёт в логах). Отсюда же лимит:
в списке держится до **8** пультов, дальше новые в него не добавляются — но в логе видны все.

### Опции `cc2500_emotion_sniffer`
| Опция | По умолчанию | Описание |
|---|---|---|
| `cc2500_emotion_id` | (авто) | Ссылка на хаб `cc2500_emotion`. Приём включается принудительно |
| `dump_raw` | `false` | Печатать все 14 байт кадра для **каждой** команды (неизвестные печатаются всегда) |

### Опции `text_sensor` платформы `cc2500_emotion_sniffer`
| Опция | Описание |
|---|---|
| `cc2500_emotion_sniffer_id` | Ссылка на `cc2500_emotion_sniffer` |
| `discovered_remotes` | Сущность со списком найденных пультов (стандартная схема `text_sensor`) |

Сниффер можно оставить и в боевом конфиге рядом с `light` — он только логирует и на управление
лампой не влияет.

## Сопряжение с лампой
Если ID своего пульта известен (см. выше), сопрягать ничего не нужно: устройство представляется
тем же ID, и лампа слушается его сразу. Сопряжение нужно, только если вы хотите завести **новый**
ID вместо клонирования существующего:

1. Перевести лампу в режим обучения (по мануалу L&S — удержание кнопки на приёмнике).
2. Нажать кнопку **«Сопряжение»** в HA — устройство широковещательно объявит свой `remote_id`
   (команда `0x60`), лампа его запомнит.
3. Готово: `remote_id` из конфига теперь управляет этой лампой.

⚠️ При своём (не клонированном) ID синхронизация состояния из эфира работать не будет: устройство
слушает только тот ID, который задан в `remote_id`, а физический пульт шлёт свой. Если важно, чтобы
нажатия пульта отражались в HA, — клонируйте ID пульта.

## Сущности в Home Assistant
- **Light** (`COLOR_TEMPERATURE`): вкл/выкл, яркость (5 ступеней → 1/25/50/75/100 %), цвет. температура.
- **Button**: «Сопряжение», «Ярче», «Темнее», «Raw send».
- **Text**: «Raw cmd (hex)», «Raw value (hex)».
- **Text sensor** (диагностика, если включён сниффер): «Найденные пульты».

Нажатия **физического пульта** отражаются в HA автоматически (вкл/выкл и цвет. температура —
точно, яркость — по шагам/оценке ramp).

## Особенности и ограничения
- **Нет обратной связи от лампы.** Состояние в HA — это наша оценка. Точные точки: абсолютные
  команды (вкл/выкл, цвет. температура) и края яркости; приём от пульта корректирует оценку.
- **Яркость — 5 дискретных ступеней**, слайдер квантуется (1/25/50/75/100 %). Протяжка в крайнее
  положение занимает до ~1 с (шаги идут через `step_interval`).
- **Команды яркости пульта одиночные** (не повторяются) → отдельные посылки иногда теряются в
  эфире; это самокорректируется на краях и при следующем действии.
- **Плавный ramp пульта** (`0x10`/`0x20` удержание, `0x40` отпускание) оценивается по времени
  (`ramp_duration`) — приблизительно.
- **При ребуте состояние восстанавливается, но НЕ передаётся лампе** (лампа помнит его сама). Если
  за время простоя ESP лампу меняли пультом, HA покажет последнее известное, а не фактическое —
  выровняется при первом действии.

## Команды протокола (кратко)
| cmd | Действие | val |
|---|---|---|
| `0x01` | Включить | текущая цвет. температура |
| `0x02` | Выключить | `0x00` |
| `0x11` / `0x21` | Яркость на шаг вверх / вниз | `0x00` |
| `0x10` / `0x20` | Начать плавный ramp вверх / вниз (~1 c), `0x40` — стоп | `0x00` |
| `0x50` | Цветовая температура (`0x00` тёплый … `0xFF` холодный) | уровень |
| `0x60` | Сопряжение | `0x00` |

Команды вне этой таблицы сниффер печатает как `UNKNOWN` вместе с полным кадром — если ваш пульт
шлёт что-то ещё, это видно сразу.

Удержание кнопки — это не одиночная посылка, а поток: `0x10`/`0x20` повторяются примерно **каждые
12 мс**, пока кнопку держат, и заканчиваются одним `0x40`. В сниффере удержание поэтому выглядит
как десятки строк в секунду.

Полный разбор (RF, регистры, кадр, находки) — в
[`captures/PROTOCOL-FINDINGS.md`](https://github.com/SergeyZh/emotion-control-re/blob/main/captures/PROTOCOL-FINDINGS.md).

## Разработка
- ESPHome в `./.venv/` (venv проекта).
- Только компиляция (проверка кода): `./.venv/bin/esphome compile bench.yaml`.
- `bench.yaml` берёт ID пульта из `secrets.yaml` (`emotion_remote_id: "…"`), чтобы он не попадал
  в репозиторий.
- Прошивка + логи: `./.venv/bin/esphome run example.yaml` (первый раз по USB `--device`, далее OTA).
- Тулчейн ESP32 кэшируется в `~/Library/Caches/esphome` → повторные сборки быстрые.
